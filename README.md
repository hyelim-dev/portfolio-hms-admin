# HMS Admin Demo Portfolio

실무에서 개발한 HMS(Admin)를 기반으로, 여러 업무 데이터가 연결되고 상태에 따라 화면과 기능이 달라지는 흐름을 포트폴리오용으로 다시 구성한 프론트엔드 데모 프로젝트입니다.

실제 회사 API와 데이터는 공개할 수 없어 MSW 기반 Mock 환경으로 구현했으며, 전체 기능을 그대로 옮기기보다 권한 분기와 상태 변화, 여러 업무 데이터가 연결되는 흐름을 중심으로 구성했습니다.

---

## 📌 Overview

실제 HMS는 상담·수강생·강의·출석·회계·통계·메시지·환경설정 등 여러 업무가 서로 연결된 구조였습니다.

데모에서는 전체 기능을 모두 구현하기보다 아래 흐름을 중심으로 실제 프로젝트에서 중요하게 다뤘던 동작을 확인할 수 있도록 구성했습니다.

- 수강생 → 강의 → 출석 → 통계로 이어지는 데이터 흐름
- 상태값에 따라 달라지는 UI와 기능
- 관리자·직원·강사 역할에 따른 권한 분기
- 출석·환불 등 상태 변경 이후 관련 데이터 반영

---

## ⚙️ Tech Stack

`Next.js` `React` `TypeScript`

`GraphQL` `Apollo Client` `Recoil`

`MSW (Mock Service Worker)`

## 🚀 Getting Started

### 1. 설치

```bash
npm install

### 2. 실행

```bash
npm run dev:admin
```

> MSW(Mock Service Worker) 기반으로 동작하며, 별도의 백엔드 없이 실행됩니다.

## 🎬 주요 Demo

### 01. 출석 상태 변경 → 출결 현황 반영

출석 상태를 변경하면 해당 데이터가 출결 현황과 통계에도 반영되도록 구성했습니다.

한 화면에서 상태를 변경하는 것으로 끝나는 게 아니라, 변경된 값이 관련된 다른 데이터에도 이어지는 흐름을 확인할 수 있습니다.

---

### 02. 상태에 따른 UI 변화

수강생의 배정 여부 등 현재 상태값에 따라 사용할 수 있는 버튼과 기능이 달라집니다.

특정 상태에서만 필요한 기능을 노출하거나 사용할 수 있도록 화면을 분기했습니다.

---

### 03. 환불 처리 흐름

환불 요청 → 승인 → 완료 순서로 상태가 변경됩니다.

환불 상태가 바뀌면 회계 데이터뿐 아니라 관련된 수강 상태에도 같이 반영되도록 구성했습니다.

---

## 🔄 데이터 흐름

데모에서는 하나의 기능이 한 화면에서만 끝나지 않고, 관련된 다른 업무 데이터에도 이어지는 흐름을 보여주는 데 중점을 뒀습니다.

- 수강생 상태 변경 → 강의 배정 / 출석부 생성
- 출석 상태 변경 → 출결 통계 반영
- 환불 상태 변경 → 회계 데이터 / 수강 상태 반영

실제 프로젝트의 전체 업무 연동을 그대로 옮긴 것은 아니며, 포트폴리오에서 확인하기 좋은 주요 흐름을 중심으로 다시 구성했습니다.

- 같은 화면에서도 권한에 따라 다른 동작 제공
- 읽기 전용 또는 기능 제한 상태 처리

## 💡 Demo 구성 방식

실제 회사 API와 데이터를 사용할 수 없기 때문에 MSW 기반으로 필요한 데이터를 구성했습니다.

- MSW 기반 GraphQL Handler 구성
- 도메인별 Mock 데이터 구성
- 일부 상태 변경은 localStorage에 저장
- 조회와 상태 변경 흐름을 확인할 수 있도록 필요한 데이터를 미리 구성
- 실제 프로젝트의 모든 기능을 구현하기보다 주요 데이터 흐름과 UI 분기를 중심으로 구현

실제 서비스 자체를 그대로 복제하기보다, 제가 맡았던 HMS의 프론트엔드 구조와 주요 동작을 확인할 수 있는 범위로 다시 만들었습니다.
